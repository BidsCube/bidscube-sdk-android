# Bidscube Android SDK 1.2.12

Android TV / Leanback remote UX, rewarded skip lock, and clearer interstitial vs rewarded rules for the **direct** BidsCube SDK (`fullVideo`). AppLovin / MAX adapters are out of scope.

## What's new

### Android TV / Leanback
- Video dialogs default to **fullscreen** on TV (`FullscreenPolicy.AUTO`).
- D-pad / remote focus stays on **Skip**, **Close**, and rewarded confirm — player surface does not steal focus.
- TV detection: Leanback feature, `UiModeManager`, Fire TV / `AFT*` heuristics.
- Banner WebViews get a TV focus ring when needed (phone focus unchanged).

### Rewarded video
- **Skip is never shown**, even if VAST `skipoffset`, default 15s, or IMA `onVideoSkippable` would allow it.
- **Back** opens leave-confirm (*Leave* → no reward; *Keep watching* → resume).
- `onUserRewarded` fires **only** after full complete, **at most once**.
- Early leave / error / incomplete pod → **no** reward.

### Interstitial video
- Skip schedule unchanged from 1.2.11:
  - VAST omits `skipoffset` → Skip after **15s**
  - `0` / `00:00:00` → Skip immediate
  - otherwise VAST time / percent
- If playback never starts within **15s**, session fails and closes (no trapped non-cancelable dialog).
- Media3 path fires VAST beacons (impression / quartiles / complete / skip) via `VastVideoTracker`.

### Publisher API
```java
BidscubeSDK.showInterstitialVideoAd(placementId, callback);
BidscubeSDK.showRewardedVideoAd(placementId, callback);
BidscubeSDK.setVideoFullscreenPolicy(VideoUiDefaults.FullscreenPolicy.AUTO);
// QA: FORCE_FULLSCREEN | FORCE_WINDOWED
```

Debug-only (`enableDebugMode(true)`): `debugPresentInterstitialVast` / `debugPresentRewardedVast`.

## Interstitial vs rewarded (quick)

| | Interstitial | Rewarded |
|--|--------------|----------|
| Skip | Per VAST / omit 15s | Never |
| Back (locked) | Consumed | Leave-confirm → no reward |
| `onUserRewarded` | Never | Full complete only (once) |
